# Connect ChatGPT to the Kotlet MCP server

> For an overview of connecting any client (including Claude), the in-app
> `/connect/mcp` onboarding page and discovery metadata, see
> [MCP onboarding](./mcp-onboarding.md). ChatGPT does not offer a public
> one-click MCP install yet, so the manual steps below remain the supported path.

## Prerequisites

- A Kotlet account with an active household.
- The production API must be running.
- If ChatGPT generates a different callback URL, add it to `OAuth:RedirectUris` in `src/backend/Kotlet.Api/appsettings.json` and deploy before connecting.

## Connect

1. Create the app.
2. Sign in through the Kotlet login page when redirected.
3. Confirm that an active household is selected.
4. Test the connection by asking ChatGPT who you are; it should read `kotlet://identity`.
5. Test read access by asking ChatGPT to list recipes or retrieve today's meal plan.

## Reconnect after permission or tool changes

If ChatGPT reports that not all permissions were granted, remove the custom app completely and create it again with the settings above. The **Reconnect** action can retain the previous consent and tool permissions.

## Attach a generated or selected recipe image

`upload_recipe_image` adds an image to an existing recipe in the active household without opening
Kotlet's UI. It accepts a native ChatGPT file reference in `file`, using
[`openai/fileParams`](https://developers.openai.com/plugins/reference#define-file-inputs). The file
schema declares `download_url`, `file_id`, `mime_type` and `file_name`; only the first two are required.
ChatGPT supplies these values from the generated or selected file. Do not invent the URL, paste a
`sandbox:` link or pass a local path: Kotlet cannot read the client's filesystem.

1. Find the existing recipe with `get_recipes` / `get_recipe`.
2. Generate or select the image in a client that can pass it as a native file reference.
3. Call `upload_recipe_image` with `recipeId`, `file`, and optional `altText` (up to 300 characters).
4. Check the returned stored image `id`, `contentUrl` and metadata, then call `get_recipe` and verify
   that image is in the gallery. A successful call adds one image; do not retry after success.

JPEG, PNG and WebP inputs are limited to 5 MB; the existing processing pipeline stores WebP and enforces
the 10-image gallery limit. `update_recipe` continues to preserve all images.

### Operator configuration and verification

The API defaults to an **empty** `McpRecipeImages:AllowedDownloadHosts` list, so downloads fail closed.
An operator must verify the exact hostname of an actual client-provided HTTPS download URL and configure
it in this list before enabling uploads. There is no wildcard, suffix match or assumed OpenAI hostname.
For example, set `McpRecipeImages__AllowedDownloadHosts__0` to a verified hostname **without** a scheme,
path or port. Add additional indexed entries only when their source has also been verified. Do not
publish signed URLs or include their query strings in configuration, screenshots or support logs.

The downloader accepts HTTPS on port 443, rejects URL credentials and fragments, resolves and checks
public IP addresses, and connects to a checked address to prevent DNS rebinding. It disables proxies,
redirects, cookies and credential forwarding, uses a 10-second deadline including body reads, enforces
a streamed 5 MB cap even without Content-Length, and rejects unsupported or mismatched media types.
The feature does not persist file IDs/download URLs or log transport exceptions/HTTP request URLs.
Expired or inaccessible references return an actionable error; request a fresh file reference instead
of changing the URL yourself.

After deploying and refreshing connector tools, an operator should test a disposable household recipe:
ask ChatGPT to generate an image and attach it, confirm `upload_recipe_image` receives a real native file
object, and verify its returned image in `get_recipe` and the Kotlet gallery. Remove the test image when
finished. If that client cannot pass the generated file as a native reference, report the limitation;
do not claim the workflow succeeded based on a local path. Local integration tests exercise real OAuth
and MCP calls with controlled download responses; they cannot prove deployed ChatGPT file availability.
